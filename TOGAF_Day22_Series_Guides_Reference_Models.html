The final Foundation day covers the TOGAF Series Guides and the two classic TOGAF reference models: the Technical Reference Model (TRM) and the Integrated Information Infrastructure Reference Model (III-RM). It also introduces business capabilities and value streams, two of the most widely used Series Guide topics.

01The TOGAF Series Guides

The Series Guides give context-specific guidance on applying the TOGAF Standard. They sit alongside the stable Fundamental Content and can be updated more often.

02The Technical Reference Model (TRM)

The TRM is a Foundation Architecture: a generic model and taxonomy of platform services that any organization can use as a starting point for its Technology Architecture.

Application Softwarebusiness applications and infrastructure applications
↕ Application Platform Interface
Application Platformthe set of platform services applications rely on
↕ Communications Infrastructure Interface
Communications Infrastructurenetworks and communications services
  • Platform services are grouped into categories, such as data management, data interchange, user interface, security, transaction processing, operating system, network services, and system and network management.
  • Qualities such as availability, security and manageability apply across the model.
  • Its value is a common vocabulary and a checklist: it helps architects make sure no important platform service is forgotten.

03The Integrated Information Infrastructure Reference Model (III-RM)

The III-RM is a Common Systems Architecture and a subset of the TRM. It expands the application software and application platform areas to support Boundaryless Information Flow™: getting the right information to the right people at the right time, securely.

ComponentRole
Business applications Brokering applications manage requests from clients to multiple servers
Information provider applications provide responses to client requests and rule-based access to data
Information consumer applications deliver content to the user and act as clients
Infrastructure applicationsDevelopment tools and management utilities
Application platformThe services that the applications run on
Interfaces and qualitiesConnect the components and apply attributes such as security and manageability

04Business Capabilities

  • A business capability is a particular ability that a business may possess or exchange to achieve a specific purpose.
  • A capability map is usually organized in levels: a few top-level capabilities, each broken down into more detailed ones.
  • Capabilities are stable and independent of the current organization structure, process or technology.
  • Heat mapping a capability map, coloring capabilities by maturity, importance or investment need, is a powerful way to target change.

05Value Streams

  • A value stream is an end-to-end collection of value-adding activities that create an overall result for a customer, stakeholder or end user.
  • It is made up of value stream stages, each with entrance and exit criteria and the value it adds.
  • Value streams describe value from the stakeholder's point of view, not the internal process.
  • Cross-mapping value stream stages to the capabilities that enable them shows which capabilities matter most for delivering value.

The takeaway

  • Series Guides give context-specific guidance and can evolve faster than the Fundamental Content.
  • The TRM is a Foundation Architecture: Application Software, Application Platform and Communications Infrastructure, joined by two interfaces.
  • The III-RM is a Common Systems Architecture and subset of the TRM, supporting Boundaryless Information Flow, with brokering, provider and consumer applications.
  • Capabilities describe what the business does; value streams show how value reaches a stakeholder; cross-mapping links the two.
