Enterprise architecture is not a one-off project; it is an ongoing capability that has to be set up, staffed, measured and improved. Today covers how TOGAF recommends establishing that capability, and two supporting tools: maturity models and the Architecture Skills Framework.

1. The Enterprise Architecture Capability

An Architecture Capability is the ability to develop, use and sustain the architecture of an organization, supported by the right organization, processes, people, governance and tools.

TOGAF recommends running the architecture function like any other operational unit of the business: with clear services, responsibilities, performance measures and continuous improvement.

2. Using the ADM to Establish the Capability

TOGAF suggests applying the ADM to the architecture practice itself:

PhaseApplied to the architecture practice
PreliminaryDefine the scope, principles, framework and governance of the practice
ASet up the project to establish the capability; agree its vision and sponsors
BThe "business" of the practice: its stakeholders, services, processes, roles, skills, organization structure and governance
CData: the architecture content and the Architecture Repository. Applications: the tools that support architecture work
DThe technology infrastructure that hosts the repository and tools
E, FPlan how to implement the capability in increments
G, HImplement the capability, then keep improving it

3. Architecture Maturity Models

Maturity models help an organization assess where its practice is today, set a target, and plan the steps to improve. In the 10th Edition this guidance is in the TOGAF Series Guide: Architecture Maturity Models.

CMMI-style levels

LevelNameTypical characteristics
1InitialAd hoc and unpredictable; success depends on individuals
2ManagedBasic processes are planned and followed at project level
3DefinedProcesses are standardized across the organization
4Quantitatively ManagedProcesses are measured and controlled with data
5OptimizingContinuous, data-driven improvement

Architecture-specific models such as the ACMM (Architecture Capability Maturity Model) use a similar scale, from 0 (none) up to 5 (measured), to assess elements of an architecture practice such as process, business linkage, senior management involvement, communication and governance.

Use maturity assessments to set a realistic target for the practice. Jumping straight to the top level is rarely achievable or worth the cost.

4. The Architecture Skills Framework

The Architecture Skills Framework, now a TOGAF Series Guide, defines the roles, skills and experience needed in an architecture practice. It helps with recruitment, training, career paths and assessing contractors.

Roles

Architecture Board members · Architecture Sponsor · Architecture Manager · Enterprise, Business, Data, Application and Technology Architects · Solution Architect · Program and Project Managers · IT Designer

Seven skill categories

Generic skillsBusiness skills and methodsEnterprise architecture skills
Program or project management skillsIT general knowledge skillsTechnical IT skills
Legal environment

Four proficiency levels

LevelNameMeaning
1BackgroundNot a required skill, but can define and manage it if needed
2AwarenessUnderstands the background, issues and implications well enough to know when to seek help
3KnowledgeDetailed knowledge; can give advice and make informed decisions
4ExpertExtensive and substantial practical experience and applied knowledge
The skills levels are Background, Awareness, Knowledge, Expert, in that order. Don't confuse them with maturity levels such as Initial, Managed or Defined.

The takeaway

  • The Architecture Capability is run like an operational business unit, with services, roles, governance and measures.
  • The ADM can be used to establish the capability: B = the practice's business, C = repository and tools, D = infrastructure.
  • Maturity models (e.g. CMMI levels 1–5, ACMM 0–5) assess today's practice and set a target.
  • The Skills Framework defines roles, seven skill categories and four proficiency levels: Background, Awareness, Knowledge, Expert.
  • In the 10th Edition, maturity models and the skills framework are Series Guides.
