Phase G: Implementation Governance

Architectural oversight of implementation: Architecture Contracts, compliance levels and dispensations

The plan is ready and implementation projects are starting. Phase G makes sure those projects actually build what the architecture described, and handles the issues that come up along the way.

01Purpose of Phase G

Phase G provides architectural oversight of the implementation. It ensures that implementation projects conform to the Target Architecture.

The architecture team does not build the solutions itself. It works with the implementation organizations, reviews their work, and approves or rejects deviations through architecture governance.

02Objectives

  • Ensure conformance with the Target Architecture by implementation projects.
  • Perform appropriate Architecture Governance functions for the solution and any implementation-driven architecture Change Requests.

03Steps

  1. Confirm scope and priorities for deployment with development management
  2. Identify deployment resources and skills
  3. Guide development of solutions deployment
  4. Perform enterprise architecture compliance reviews
  5. Implement business and IT operations
  6. Perform post-implementation review and close the implementation

04Architecture Contracts

An Architecture Contract is a joint agreement between development partners and sponsors on the deliverables, quality and fitness-for-purpose of an architecture.
  • Contracts may exist between the architecture function and business users (for the architecture work itself), or between the architecture function and a development partner (for implementing the architecture).
  • Successful implementation is achieved through effective architecture governance, and the contract is the governance tool for this.
  • Typical contents include: introduction and background, nature of the agreement, scope, architecture and strategic principles, requirements, development and conformance checkpoints, success criteria, timelines, and signatures.

05Levels of Architecture Compliance

TOGAF defines six levels for describing how an implementation relates to the architecture specification:

LevelMeaning
IrrelevantThe implementation has no features in common with the architecture specification
ConsistentFeatures in common are implemented according to the spec, but some spec features are not implemented and the implementation has other features not covered by the spec
CompliantSome spec features are not implemented, but all features that are implemented are covered by the spec and follow it
ConformantAll spec features are implemented according to the spec, but some extra features are implemented that are not in it
Fully ConformantFull correspondence between the architecture specification and the implementation
Non-conformantAny of the above where some spec features are implemented not in accordance with the spec
Memory hook: Compliant = "only what's in the spec, but not all of it". Conformant = "all of the spec, plus extras". Fully Conformant = "exactly the spec".
Non-conformant is about implementing spec features incorrectly. Missing or extra features alone do not make an implementation non-conformant.

06Dispensations

When an implementation cannot comply, the Architecture Board may grant a dispensation. A dispensation is:

  • a formal, recorded exception to the architecture;
  • time-bound, so it expires and forces the issue to be revisited;
  • often linked to conditions such as a plan to become compliant.

07Outputs

  • Architecture Contract (signed)
  • Compliance Assessments
  • Change Requests
  • Architecture-compliant solutions deployed, including the implemented system, a populated Architecture Repository, recommendations and dispensations, recommendations on service delivery requirements and performance metrics, SLAs, the Architecture Vision updated after implementation, and the Architecture Definition Document updated after implementation

The takeaway

  • Phase G provides architectural oversight so implementation projects conform to the Target Architecture.
  • The Architecture Contract is a joint agreement on deliverables, quality and fitness-for-purpose, and it is signed in Phase G.
  • Six compliance levels: Irrelevant, Consistent, Compliant, Conformant, Fully Conformant, Non-conformant.
  • The Architecture Board can grant time-bound dispensations.
  • Outputs: signed Architecture Contract, Compliance Assessments, Change Requests, and architecture-compliant solutions.
