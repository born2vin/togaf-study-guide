Phase F: Migration Planning

Finalizing the roadmap and migration plan: business value, prioritization and the four management frameworks

Phase E produced an initial roadmap and plan. Phase F finalizes them: it puts a business value and cost on each work package, prioritizes, and makes sure the plan fits the way the enterprise already manages change.

01Purpose of Phase F

Phase F addresses migration planning: how to move from the Baseline to the Target Architectures by finalizing a detailed Implementation and Migration Plan.

02Objectives

  • Finalize the Architecture Roadmap and the supporting Implementation and Migration Plan.
  • Ensure the Implementation and Migration Plan is coordinated with the enterprise's approach to managing and implementing change in its overall change portfolio.
  • Ensure that the business value and cost of work packages and Transition Architectures are understood by key stakeholders.

03Steps

  1. Confirm management framework interactions for the Implementation and Migration Plan
  2. Assign a business value to each work package
  3. Estimate resource requirements, project timings, and availability and delivery vehicles
  4. Prioritize the migration projects through a cost/benefit assessment and risk validation
  5. Confirm the Architecture Roadmap and update the Architecture Definition Document
  6. Complete the Implementation and Migration Plan
  7. Complete the architecture development cycle and document lessons learned

04The Four Management Frameworks

The Implementation and Migration Plan must fit with the frameworks the enterprise already uses to manage change. TOGAF names four that must work together:

FrameworkRole
Business PlanningConceives, plans and budgets for the change that the enterprise needs
Enterprise ArchitectureStructures and gives context to the change
Portfolio / Project ManagementCoordinates, designs and builds the business systems that deliver the change
Operations ManagementIntegrates, operates and maintains the deliverables
Memory hook: Plan it, shape it, build it, run it (Business Planning, EA, Portfolio/Project Management, Operations Management).

05Assigning Business Value

To prioritize work packages, Phase F assigns each one a business value, using factors such as:

  • Performance evaluation criteria used by the portfolio and capital planning processes
  • Return on investment criteria
  • Business value and contribution to critical success factors (CSFs)
  • Measures of effectiveness and strategic fit

The Business Value Assessment technique plots each work package on a matrix of value against risk, making the priorities easy to see. Prioritization then takes account of cost/benefit, risk, and dependencies.

Risk validation in Phase F looks again at the risks identified in Phase A and refined in Phase E, and confirms that the residual risk of each work package is acceptable.

06Outputs

  • Finalized Implementation and Migration Plan
  • Finalized Architecture Definition Document
  • Finalized Architecture Requirements Specification
  • Finalized Architecture Roadmap
  • Finalized Transition Architectures
  • Reusable Architecture Building Blocks
  • Requests for Architecture Work for the architecture aspects of implementation projects, if needed
  • Architecture Contracts for implementation projects
  • Implementation Governance Model
  • Change Requests for the Architecture Capability arising from lessons learned
Phase F is where most architecture deliverables become "finalized". Phase F also produces the Implementation Governance Model and the Architecture Contracts that Phase G will use; they are signed in Phase G.

The takeaway

  • Phase F finalizes the Architecture Roadmap and Implementation and Migration Plan.
  • The plan must fit the four management frameworks: Business Planning, EA, Portfolio/Project Management and Operations Management.
  • Each work package gets a business value; projects are prioritized by cost/benefit and risk.
  • Phase F ends the architecture development cycle and captures lessons learned.
  • Outputs include the Implementation Governance Model and Architecture Contracts for Phase G.
